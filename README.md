# Yaqeen

Source-backed rulings from your marja.

Yaqeen is a hackathon MVP for a retrieval-based Shia marja ruling assistant. The app lets a user select a marja, ask a fiqh question, and receive either a short cited answer from verified records or a safe Not Found response.

## Current Build

The current build is demo-capable:

- Next.js App Router frontend
- Marja selector
- Question input
- Suggested questions
- Source cards
- Compare All table
- `POST /api/ask` endpoint
- 12 exact-source verified demo records in `data/rulings.json`
- Safe Not Found handling when no verified record matches
- Retrieval-first AI/RAG answer generation with safe deterministic fallback
- Optional vector retrieval with keyword fallback
- Runtime dataset schema validation

The canonical dataset is expected at:

```text
data/rulings.json
```

The dataset is present for the MVP. If no relevant verified record is retrieved, the app intentionally returns Not Found rather than answering from model knowledge.

## AI Layer

The API always retrieves verified records before calling an AI provider. The model receives only a compact source packet and a strict source-only system prompt. Citations are generated by the backend from `data/rulings.json`, not by the model.

AI is optional. If it is disabled, unavailable, or returns unsafe output, the API falls back to a deterministic answer using the top retrieved source record.

Supported environment variables:

```text
YAQEEN_AI_ENABLED=true
YAQEEN_AI_PROVIDER=openai | ollama | mock | none
YAQEEN_AI_MODEL=<model-name>
OPENAI_API_KEY=<key>
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_TIMEOUT_MS=60000
```

`OLLAMA_TIMEOUT_MS` controls how long the Ollama provider waits before aborting the request (default: 60000 ms). Local models can be slow on first load; increase this if you see timeout fallbacks.

Examples:

```text
YAQEEN_AI_ENABLED=true
YAQEEN_AI_PROVIDER=openai
YAQEEN_AI_MODEL=gpt-4o-mini
OPENAI_API_KEY=...
```

```text
YAQEEN_AI_ENABLED=true
YAQEEN_AI_PROVIDER=ollama
YAQEEN_AI_MODEL=llama3.2:3b
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_TIMEOUT_MS=60000
```

Tests use the mock provider and do not call external AI services.

Token streaming is not implemented yet; the current API is non-streaming for demo stability.

## Vector Retrieval

Vector retrieval is optional. The source of truth remains `data/rulings.json`; embeddings only help find verified records.

Generate or refresh embeddings with:

```bash
npm run build:embeddings
```

Embeddings are written to:

```text
data/ruling-embeddings.json
```

Required for generation:

```text
OPENAI_API_KEY=...
YAQEEN_EMBEDDINGS_ENABLED=true
YAQEEN_EMBEDDING_MODEL=text-embedding-3-small
```

If embeddings are disabled, missing, stale, or the API key is unavailable, Yaqeen falls back to deterministic keyword retrieval.

## Local AI Test

1. Start Ollama.
2. Pull model:
   `ollama pull llama3.2:3b`
3. Set `.env.local`:
   ```text
   YAQEEN_AI_ENABLED=true
   YAQEEN_AI_PROVIDER=ollama
   YAQEEN_AI_MODEL=llama3.2:3b
   OLLAMA_BASE_URL=http://localhost:11434
   OLLAMA_TIMEOUT_MS=60000
   ```
4. Run:
   `npm run dev`
5. Ask a covered question (e.g. "What breaks wudhu?" with Sistani selected).
6. Confirm the badge shows `Generated with: AI answer · ollama · llama3.2:3b`.

## Local Embeddings

1. Pull embedding model:
   `ollama pull nomic-embed-text`
2. Set `.env.local`:
   ```text
   YAQEEN_EMBEDDINGS_ENABLED=true
   YAQEEN_EMBEDDING_PROVIDER=ollama
   YAQEEN_EMBEDDING_MODEL=nomic-embed-text
   OLLAMA_BASE_URL=http://localhost:11434
   ```
3. Run:
   `npm run build:embeddings`

If embeddings are missing or disabled, the app falls back to keyword retrieval automatically.

## Dataset Expansion

Background expansion files stay separate until verified. Only exact-source verified records should be copied into `data/rulings.json`.

Records marked `needs_review` or `deprecated` are not answer-eligible. Run `npm run test:dataset` after editing the dataset.
